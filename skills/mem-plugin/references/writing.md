# 写入、纠正与遗忘

仅在用户明确要求或已有授权覆盖本次保存时写入，保存可独立理解且含必要限定条件的事实，不默认保存整段对话。

## 原子记忆的粒度

一次 memory.record 保存一条 Note，服务端保留提交正文，不自动拆分。以能否独立检索、验证或纠正为标准：同一主题的独立研究发现、运行结果和复现限制分别调用 record，各带必要的主体、样本范围和来源。不要把整份阶段复盘塞进一条 Note，也不按句号机械拆分。

一个完整决策及其理由可以保留为一条；同一次评测的收益、回撤、Sharpe 等指标可以放在同一个结果事件中，数值可保存到 attributes 或 domain_payload。不同 Note 沿用真实的任务、轮次、阶段和报告来源，不为拆分而编造关联信息或重复复制全部参数。

## 已授权的研究与工作任务

用户或宿主授权本轮研究记忆后，及时保存以下信息，不等待再次逐条授权：已确认的任务约束、可复用的实测结论、方案取舍、重要失败及原因、已完成的决策。可以使用 memory_type=project、decision 等既有类型，不为研究任务发明一套新工具或存储模型。

例如，当前可见样本上的回测否定了某个参数方案，可以保存“在本次已开放样本和已验证配置下，方案 X 未达到当前目标；保留方案 Y，理由为 Z”，同时记录实际来源。不可把它改写成“策略 X 永远无效”，也不能把研发回测当成未执行的正式评测。来源可在 source_ref 中带上任务 ID、阶段、文档或报告位置、已知的样本范围和版本；不存在的信息省略，不猜测收益、时间或哈希。

用户约束用明确事实表达；研究假设若确需保留，必须标注未验证状态和置信限制。不要保存完整行情表、完整工具轨迹、全部搜索结果、思考过程或密钥。文件已写入 RESEARCH.md/CHANGELOG.md 不代表写入过记忆；以 memory.record 的成功返回为准。超时复用原幂等键，未授权的纠正和删除仍须遵守原边界。

最终报告实际可见后，在已有任务记忆授权内保存一条结果事件：记录完成状态、评测覆盖范围、汇总指标、实际策略版本及报告来源。正式评测与研发回测分别标明；不覆盖历史阶段结果，不提前推测尚未运行的成绩。宿主若在 Agent 结束后才生成报告，应再提供收尾调用机会，或根据结构化报告直接调用 record；Skill 本身无法观察未提供的结果。

memory.record(content, idempotency_key=...) 返回已提交记忆。默认 Agent 私有；共享范围必须符合宿主授权，不自行扩大范围。embedding_status=pending 表示记忆已保存，但尚未向量化。

为一次逻辑写入使用稳定幂等键。超时重试复用原键和相同输入；不同事实使用新键。同一键更换内容会冲突，不能盲目重复创建记忆。

需要时提供 attributes、domain_payload、source_ref 和已知的 occurred_at/valid_from/valid_until；时间带时区，不猜测缺失时间。沿用已有结构化字段含义和数值表示，金额或 ID 不用模糊文本代替。正文默认上限 16000 字符，过长内容提炼为可独立理解的事实，不默认保存整份文档或密钥。

纠正前按 ID 核对目标，调用 memory.feedback(memory_id, action=correct, content=新事实, idempotency_key=...)。结果保留旧 memory，并在 replacement 中返回新事实与新 ID。以后使用 replacement ID；旧事实和受影响派生结果变为 stale，不覆盖原文。同一纠正请求重试沿用幂等键。

明确确认或否定时，可使用 action=confirm 或 reject，不附带新正文。confirm 记录确认时间，不自动恢复 stale；reject 使目标和依赖其内容的派生结果失效。

忘记时使用 memory.forget(memory_id)。操作会清理目标纠正链及其派生结果、版本、关系、向量和任务，保留无正文的最小删除审计。不要把宽泛搜索全部命中直接当作批量删除目标；有实质歧义时先定位目标。

明确删除的派生 ID 有不含正文的标记，阻止相同分组身份被后台恢复。删除派生摘要不等于删除仍保留的原始事实；用户要求忘记事实本身时先按 atomic_source_ids 定位 L0，并按授权范围操作。

deleted=false 表示当前范围中没有删除目标，不报告本次成功删除。工具状态未知时先核对，不宣称完成；数据库之外的备份和物理介质擦除不在当前工具承诺内。
